# Требования: цикл с точной подзадачей

Цели и границы — в [brief.md](brief.md), факты — в [research.md](research.md).

## Истории и критерии приёмки

### US-1: Команда получает на датасете организаторов S ниже, чем даёт локальный поиск, за приемлемое время (P1, цель G-1)

- **AC-1.1** WHEN сервис запущен с циклом (свойство `heatnet.exact.iterations` больше нуля, значение по умолчанию задаёт исполнитель) THE SYSTEM SHALL дать на `data/real/dataset.geojson` S варианта 1 не выше 12,80, а на сценах `data/synth/medium-{1,2,3}.geojson` S не выше базового плюс 0,10 — проверка: `python3 scripts/gates/exact_bench.py` печатает `EXACT GAIN OK`; база — `data/out/bench/<сцена>-base.geojson` от `scripts/bench.sh base` на коммите до цикла.
- **AC-1.2** THE SYSTEM SHALL быть детерминированным с циклом: два прогона датасета дают побайтно равные выходы — проверка: тот же скрипт печатает `EXACT DETERMINISTIC`.
- **AC-1.3** THE SYSTEM SHALL выдавать с циклом выход, который проходит валидатор `heatcheck` без нарушений на всех четырёх сценах стенда — проверка: тот же скрипт печатает `EXACT VALID`.
- **AC-1.4** WHEN цикл включён THE SYSTEM SHALL писать в лог на уровне INFO по строке на итерацию: номер, снятые ОКС, S до и после, принято или нет, причина отказа — проверка: `java -Dheatnet.exact.iterations=3 -jar target/heatnet.jar --cli data/samples/small-1.geojson /tmp/x.geojson 2>&1 | grep -c "exact:"` даёт не меньше 3.

### US-2: Разработчик понимает устройство цикла по документации (P2, цель G-1)

- **AC-2.1** THE SYSTEM SHALL иметь описание цикла в `architecture/ARCHITECTURE.md`: выбор подмножества, граф области, точная модель, починка, память подмножеств, свойства `heatnet.exact.*` со значениями по умолчанию — проверка: `grep -c "heatnet.exact" architecture/ARCHITECTURE.md` не меньше 2 и в файле есть заголовок раздела со словами «точной подзадачей».
- **AC-2.2** THE SYSTEM SHALL иметь запись `H-6` в `docs/research/hypotheses.md` с итоговыми числами стенда и решением, включать ли цикл по умолчанию — проверка: `grep -c "### H-6" docs/research/hypotheses.md` равно 1.

### US-3: Проверяющий сверяет эксперименты скриптом, а не на слово (P1, цель G-3)

- **AC-3.1** THE SYSTEM SHALL вести журнал `docs/research/exact-subproblem/experiments.md` с таблицей, где у каждого эксперимента ID `E-n`, дата, коммит, сцена, параметры, S до, S после, секунды, файл выхода в `data/out/exact/` и вывод; не меньше 6 записей, не меньше 3 разных сцен, хотя бы одна запись с выводом «отклонено» или «хуже»; S в файле совпадает с журналом до 0,001; коммит существует — проверка: `python3 scripts/gates/exact_journal.py` печатает `EXACT JOURNAL OK`.
- **AC-3.2** THE SYSTEM SHALL хранить выходы экспериментов как файлы `data/out/exact/<E-n>-<сцена>.geojson` и не удалять их до сдачи — проверка: входит в AC-3.1, скрипт читает каждый файл.

### US-0: Что не должно измениться (цель G-2)

- **AC-0.1** WHEN `heatnet.exact.iterations=0` THE SYSTEM SHALL давать на четырёх сценах стенда выходы, побайтно равные базовым, и считать датасет не дольше 60 секунд — проверка: `python3 scripts/gates/exact_bench.py` печатает `EXACT OFF UNCHANGED`.
- **AC-0.2** THE SYSTEM SHALL проходить прежние проверки: `make test-unit`, `make test-python`, `make test-scenarios` — проверка: `scripts/gates/exact_regress.sh` печатает `REGRESS OK` (скрипт запускает три цели и печатает маркер только при трёх успехах).

## Нефункциональные требования

- **NFR-1** Датасет организаторов с циклом при значении `heatnet.exact.iterations` по умолчанию считается не дольше 360 секунд стенных на машине исполнителя — источник числа: R-5, цикл окупается после 300–400 CPU-с на прототипе; замер: `python3 scripts/gates/exact_bench.py` печатает `EXACT TIME OK`.
- **NFR-2** Одна итерация цикла (граф области, точная модель, починка) на датасете не дольше 15 секунд — источник числа: R-2, подзадача 1,1–1,8 CPU-с и починка 10–40 CPU-с на прототипе, Java после ускорений быстрее; замер: строки лога AC-1.4 содержат время итерации, максимум по логу датасета не больше 15 000 мс — проверка: `python3 scripts/gates/exact_iteration.py` печатает `EXACT ITERATION OK`.

## Ограничения

- **C-1** Java 11, Spring Boot 2.6.3, без новых зависимостей: динамика Дрейфуса–Вагнера и Флойд–Уоршелл пишутся своими руками, решатель не подключается (NG-1).
- **C-2** Детерминированность: никаких стенных часов в критериях остановки и никаких недетерминированных коллекций в порядке перебора; случайность только через `java.util.Random` с фиксированным сидом.
- **C-3** Формат выхода, `rules/rules.json`, валидатор и сценарии не меняются (NG-3).
- **C-4** Работа в ветке `exact-subproblem`, коммиты без трейлеров атрибуции, в `main` не пушить.

## Допущения

Приняты без подтверждения. Если допущение окажется ложным, план меняется.

- **A-1** Число итераций цикла, при котором датасет опускается до 12,80, укладывается в 360 секунд Java — если ложно: NFR-1 или AC-1.1 не выполняются одновременно, исполнитель выбирает значение по умолчанию, при котором проходит NFR-1, а AC-1.1 помечает ABANDON с числами.
- **A-2** На сценах medium цикл не ухудшает S больше чем на 0,1 — если ложно: цикл по умолчанию выключается, AC-1.1 переписывается под «с явно включённым циклом».
- **A-3** Прототип `tools/research/heatopt/` читаем и его алгоритм переносится без Python-зависимостей — если ложно: исполнитель реализует по описанию из research.md.
