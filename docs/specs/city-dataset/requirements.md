# Требования: большой реалистичный датасет

Цели и границы — в [brief.md](brief.md), факты — в [research.md](research.md).

## Истории и критерии приёмки

### US-1: Команда получает файл «город» для проверки объёма и памяти (P1, цель G-1)

- **AC-1.1** WHEN выполнена команда `make synth-city` (или `python -m heatsynth --preset city --seed 1 --out data/synth/city-1.geojson`) THE SYSTEM SHALL создать файл размером не меньше 3 ГБ с не меньше чем 1 000 000 объектов `Feature` — проверка: `python3 scripts/gates/city_dataset.py city` печатает `CITY FILE OK`.
- **AC-1.2** THE SYSTEM SHALL выдавать файл, который проходит `heatsynth.check` без ошибок: схема формата датасета (R-1), геометрии валидны по OGC, здания не пересекаются друг с другом и с сетью, каждая точка подключения лежит внутри своего здания, сеть связана с источником и без циклов, диаметры не растут от источника к концам — проверка: входит в `city_dataset.py city`, `heatsynth.check` обязан читать файл потоком и завершаться на 3 ГБ.
- **AC-1.3** THE SYSTEM SHALL иметь файл «город», который сервис считает до конца: CLI с кучей 12 ГБ завершается кодом 0, а выход содержит `variant_summary` — проверка: `scripts/gates/city_run.sh` печатает `CITY RUN OK` и пиковую память.

### US-2: Команда получает плотные сцены для замера качества (P1, цель G-2)

- **AC-2.1** WHEN выполнена команда `make synth-dense` THE SYSTEM SHALL создать `data/synth/dense-50.geojson`, `dense-100.geojson`, `dense-200.geojson` с ровно 50, 100 и 200 точками подключения в квартале не больше 1,5 × 1,5 км, каждый проходит `heatsynth.check` — проверка: `python3 scripts/gates/city_dataset.py dense` печатает `DENSE FILES OK`.
- **AC-2.2** THE SYSTEM SHALL строить сцены «густо» так, что сервис подключает все ОКС: в выходе варианта 1 `unconnected_oks_ids` пуст на всех трёх сценах — проверка: `scripts/gates/dense_run.sh` печатает `DENSE RUN OK` с S и временем каждой сцены.

### US-3: Команда видит, что синтетика похожа на датасет организаторов (P1, цель G-3)

- **AC-3.1** THE SYSTEM SHALL иметь отчёт `docs/testing/dataset-report.md` с таблицей распределений по трём наборам (организаторы, город, густо-200): число объектов по типам, медиана и децили числа вершин здания, площади здания, расстояния до ближайшего здания, длины участка сети, доля зданий с дворами; у города медиана вершин 10–20 и медиана площади 900–3600 м², медиана размера фичи не больше 3 КБ, координаты с 9 знаками после запятой — проверка: `python3 scripts/gates/city_dataset.py stats` печатает `DATASET STATS OK`.
- **AC-3.2** THE SYSTEM SHALL генерировать застройку кварталами вдоль уличной сетки с произвольным углом поворота: дороги как `restriction` типа `road` полосами 10–30 м, здания в кварталах между ними, сеть теплоснабжения вдоль улиц, водоёмы и железная дорога как в датасете — проверка: в отчёте раздел «Как устроена сцена» со схемой и числами (число кварталов, дорог, доля площади под дорогами), и в файле «город» не меньше 1000 объектов `road`: `grep -c '"road"' data/synth/city-1.geojson` не меньше 1000.

### US-0: Что не должно измениться (цели G-1, G-2)

- **AC-0.1** THE SYSTEM SHALL по-прежнему генерировать пресеты `small`, `medium`, `large` теми же командами с тем же результатом: `python -m heatsynth --preset medium --seed 1` даёт файл, побайтно равный сохранённому до правок — проверка: `scripts/gates/synth_regress.sh` печатает `SYNTH REGRESS OK` (скрипт сравнивает с копией `data/synth/medium-1.geojson`, снятой на коммите до правок).
- **AC-0.2** THE SYSTEM SHALL проходить прежние тесты `make test-python` и `make test-scenarios` — проверка: `scripts/gates/synth_regress.sh` печатает `SYNTH TESTS OK`.

## Нефункциональные требования

- **NFR-1** Генерация файла «город» не дольше 30 минут и не больше 4 ГБ памяти процесса генератора — источник числа: бюджет brief.md, генерация должна повторяться на машине команды; замер: `/usr/bin/time -l` в `make synth-city`, числа в отчёте, проверка: `python3 scripts/gates/city_dataset.py stats` читает из отчёта строку «генерация: … с, … МБ» и печатает `CITY GEN TIME OK`, если не больше 1800 с и 4096 МБ.
- **NFR-2** Расчёт файла «город» сервисом с кучей 12 ГБ не дольше 60 минут — источник числа: ТЗ времени не ограничивает, час выбран как предел терпения на защите; замер: `scripts/gates/city_run.sh` печатает время и `CITY RUN OK`.

## Ограничения

- **C-1** Формат файла ровно как у датасета организаторов (R-1): `restriction_type = oks` для зданий, точки подключения с `flow_tph` без `oks_id`, сеть без `flow_tph` и `upstream_object_id`, камеры без `diameter`, целые `id`, `MultiPolygon` у зданий, WGS 84 с 9 знаками.
- **C-2** Генератор и проверка пишут и читают потоком: в памяти не больше одного тайла или одной фичи, никакого `json.load` файла целиком.
- **C-3** Детерминированность по сиду: два запуска с одним сидом дают побайтно равные файлы, тайлы субагентов тоже по сиду тайла.
- **C-4** Только текущий Python-проект `tools/` с его зависимостями (shapely, pyproj, numpy); новые зависимости не добавлять.
- **C-5** Файлы `data/synth/city-*.geojson` и `data/synth/dense-*.geojson` в git не попадают; в репозиторий идут генератор, тесты, отчёт и скрипты.
- **C-6** Субагентов не больше 10 одновременно; главный агент собирает итог сам и перепроверяет гейты после каждого возврата.

## Допущения

Приняты без подтверждения. Если допущение окажется ложным, план меняется.

- **A-1** Уличная сетка под произвольным углом с кварталами 100–300 м даёт застройку, на которой трассы ведут себя как на датасете организаторов — если ложно: отчёт всё равно показывает распределения, сцена остаётся полезной для памяти и нагрузки.
- **A-2** Сервису хватает кучи 12 ГБ на файл 3 ГБ — если ложно: AC-1.3 и NFR-2 получают ABANDON с числами пиковой памяти, это главная находка пакета для docs/load-limits.md.
- **A-3** Миллион зданий с медианой 14 вершин укладывается в 3 ГБ при 9 знаках координат — если ложно: число зданий поднимается, пока файл не достигнет 3 ГБ, распределения не меняются.
