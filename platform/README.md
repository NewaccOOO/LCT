# Теплосеть 3D — платформа инженера

Веб-платформа для инженера тепловых сетей. Она открывает исходные данные и результат сервиса трассировки и показывает
в объёме, как новая труба идёт под землёй мимо газа, кабелей, водопровода, канализации и существующей теплосети. Сцену можно
крутить, летать над землёй и под ней, пройти «пролётом» вдоль трассы от врезки до здания, разобрать пересечения по
высоте на продольном профиле, сравнить варианты и отправить свой расчёт на сервер.

Управление и раскладка повторяют программы, к которым инженер привык (закон Якоба): Яндекс/Google Карты,
AutoCAD/Revit/Navisworks/Civil 3D и игры с WASD. Почему именно так — [docs/DESIGN.md](docs/DESIGN.md),
результаты инженерных ревью по циклам — [docs/UX-REVIEW.md](docs/UX-REVIEW.md).

## Запуск

```bash
make platform                 # http://localhost:8091 — демо-наборы, без сервиса и базы
make up                       # сервис с базой: платформа на http://localhost:8080, расчёты через API
make platform-test            # тесты модели сцены (node 18+)
```

Нужен любой современный браузер с WebGL 2 (Chrome, Edge, Firefox, Safari 15+). Интернет не нужен: three.js лежит в
`vendor/`. Открывать `index.html` двойным щелчком нельзя — ES-модули работают только по http.

Откуда берутся данные:

| Источник | Как |
|---|---|
| Демо-наборы `demo/` | открываются сразу; список — `demo/index.json`, свой набор: `python3 platform/tools/cut_demo.py ВХОД ВЫХОД --name имя --title "Название"` |
| Свои файлы | **Файл → Открыть данные → Свои файлы** или перетащить GeoJSON в окно: исходные данные и, если есть, результат трассировки (какой файл какой, платформа определяет сама). Отчёт покажет, что пропущено и почему. Файлы сохраняются в браузере (`?ds=local`) и после F5 открываются снова |
| Сервис | если платформа открыта с адреса сервиса: **Файл → Новый расчёт на сервере** (с флажком «С учётом глубины» — `POST /api/v1/jobs?depth=true`) и **История расчётов** |

Адрес страницы хранит набор, вариант, выбранный объект и камеру: `?ds=spb-kupchino#v=1&sel=oks:cp-…&cam=…`.
Коллега, открыв ссылку из **Скопировать ссылку**, увидит тот же вид.

## Что на экране

- **Шапка**: меню «Файл», набор данных, поиск по номеру здания, участка, камеры, адресу или координатам, варианты
  решения (у варианта с наименьшим S подпись «лучший»), справка.
- **Слева**: «Обзор» (показатель S, стоимость по статьям, сравнение вариантов, другой вариант поверх текущего белым пунктиром),
  «Здания» (подключено/нет, длина трассы, проблемы), «Проблемы» (пересечения с недостаточным зазором, уклон и
  глубина), «Слои» (вертикальный масштаб «Глубина ×N», прозрачность земли, здания объёмом/контуром, цвет новой сети
  по Ду/проблемам/глубине, слои с количеством, таблица глубин коммуникаций).
- **Сцена**: у новой сети свой бирюзовый цвет (у существующих: теплосеть красная, газ жёлтый, кабель фиолетовый,
  водопровод синий, канализация коричневая), спецпереход — прозрачный футляр, проблема по высоте — малиновая метка с
  иглой до земли; трубы настоящего габарита по Таблице 1 (вертикаль растягивается, диаметры — нет), колодцы камер,
  здания объёмом по этажности, полупрозрачная земля с сеткой 10/100 м, проекция трассы на землю пунктиром, у
  выбранной трассы — отвесы до земли, подписи глубины, камер и пересечений. Справа — куб видов и панель навигации,
  слева внизу — условные обозначения и масштабная линейка, справа внизу — метка вертикального масштаба.
- **Справа**: свойства выбранного и что с ним можно сделать. У пересечения — текущий и нужный зазор и два способа
  обхода: поднять трубу не глубже X или опустить не мельче Y с коэффициентом стоимости Kгл. Кнопки «Показать обход
  сверху» и «Показать обход снизу» рисуют обход в 3D и на профиле.
- **Снизу**: продольный профиль трассы (как Profile View в Civil 3D) — глубина по длине, пересекаемые коммуникации с
  зоной нужного зазора, дороги и спецпереходы, пикетаж ПК и подвал «Ду / Уклон, ‰ / Глубина верха, м / Длина, м».
  Колесо меняет масштаб по длине, наведение показывает точку в 3D, щелчок переносит камеру к ней. В строке состояния —
  координаты и глубина под курсором и подсказки мыши для текущего режима.

## Устройство

| Файл | Что делает |
|---|---|
| `index.html`, `css/app.css` | раскладка, тёмная тема, мобильная версия (панель слева — выдвижная, свойства — нижний лист) |
| `js/model.js` | вход + выход → сцена в метрах: коммуникации, поверхности, здания к подключению, участки с глубиной по вершинам, пересечения и проверки раздела 14 CONSTRAINTS.md (та же логика, что `scripts/ui3d/prep.py`), трасса от врезки до здания |
| `js/viewer.js` | three.js: трубы экземплярами цилиндров, колодцы, здания, земля-шейдер с сеткой, линии постоянной толщины для дальнего плана, подсветка трассы, срез, выбор объектов своей сеткой отрезков с допуском в пикселях |
| `js/controls.js` | камера: сдвиг «за точку», вращение вокруг точки под курсором, масштаб к курсору, полёт, жесты тачпада и телефона, плавные перелёты |
| `js/viewcube.js` | куб видов со сторонами света и компасом |
| `js/profile.js` | продольный профиль на canvas |
| `js/main.js` | загрузка (демо, файлы, сервис), панели, выбор, поиск, меню, срез, линейка, пролёт, адрес страницы |
| `tools/cut_demo.py` | вырезает демо-набор вокруг новой сети |
| `test/model.test.mjs` | тесты модели на демо-наборах |

Сервис отдаёт платформу на `/` (ресурс `platform/` в `pom.xml` копируется в `static/`), поэтому с `make up` она
работает с API без настроек CORS. Москва (исходные данные 48 МБ, 130 тыс. объектов, 5,5 тыс. участков) открывается
в браузере примерно за 15 с: 10 млн треугольников, выбор объекта под курсором занимает доли миллисекунды.
