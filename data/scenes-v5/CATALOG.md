# Тестовые сцены трассировки

Набор проверяет, что сервис ведёт себя разумно в типичных и краевых ситуациях: врезка в камеру и в трубу,
переходы улиц и коммуникаций, обход запретных территорий, дворы, дальние дома, большие расходы, разветвлённая
сеть и предельная длина, плохой вход, режим глубины. Основа сцен — реальная застройка OpenStreetMap из сборок
городов (`data/cities/moscow/input.geojson` — северо-запад Москвы от Хорошёво-Мнёвников до Пресни,
`data/cities/spb/input.geojson` — Купчино). Существующая теплосеть и подземные линии в этих сборках частью
восстановлены по схемам, частью достроены по нормативам (`docs/real-cities.md`); здания, улицы, ж/д, вода, парки
и территории реальные. Синтетика — там, где нужна точная геометрия: предельная длина на дереве, пороги выбора,
поле на километры, линейные ограничения. Есть датасет организаторов целиком (REAL) и 20 случаев режима глубины
(DEPTH).

## Когда сцена пройдена

Сцена пройдена, если выполнены все ожидания `expect.must` и `check18.py --no-shape --core-types` не нашёл
нарушений (для сцен с `run_args = ["--depth"]` — `check18.py --no-shape --core-types --depth`). Ключ `--no-shape`
отключает эвристики формы трассы B16–B23, ключ `--core-types` — нарушения по дополнительным типам ограничений
(metro, sewer, water_supply и неизвестные типы): по разъяснению 9 их поддержка необязательна.

«Не проверить» в `must` считается провалом. Исключение одно: `unconnected` без `output.criteria.json`, когда
причину неподключения прочитать неоткуда. Общий ключ `no_crash` стоит во всех сценах, где ждут выход, поэтому
падение сервиса проваливает сцену явно. Сцены с `must.diagnostic` (IN-03, IN-04, IN-05, IN-06, IN-12, IN-13)
ждут отказа: сцена пройдена, если сервис завершился с ненулевым кодом и назвал в выводе объект. Других ключей
`must` у таких сцен нет, check18 к ним не применяется, потому что выхода нет. `expect.should` в критерий не
входит: это ориентиры проектировщика.

Сгенерировать заново (детерминированно по seed, около десяти минут) и проверить ожидания:

```bash
uv run --project tools python -m heatscenes --clean                       # все сцены в data/scenes-v5 и этот каталог
uv run --project tools python -m heatscenes --only CROSS TIE-01           # часть сцен
uv run --project tools python -m heatscenes --root data/другая-папка      # другая папка набора
uv run --project tools python tools/scenes/render.py data/scenes-v5/*/   # input.png
uv run --project tools python tools/scenes/render.py data/scenes-v5/TIE-01 --out OUT.geojson  # result.png
uv run --project tools python -m heatscenes.expect_check data/scenes-v5  # проверка ожиданий по output.geojson
```

## Что лежит в папке сцены

- `input.geojson` — вход в формате датасета организаторов (редакция 18.09): все здания — `restriction` с
  `restriction_type = oks`, расход на точке подключения, у сети только `diameter`, у камер только `id`. Новые
  дома помечены служебным свойством `_new`, сервис его игнорирует.
- `scene.json` — описание: `title`, `description`, `source` (район, bbox в WGS 84, размер окна, правки окна),
  `rules` (пункты правил), `expect`, `points` (точки подключения и расходы), `reference` (кратчайший допустимый
  путь от точки до сети), `run_args` (ключи запуска сервиса: у сцен DEPTH — `--depth`), `objects`.
- `input.png` — картинка входа: новые дома оранжевые, теплосеть оранжевая (толщина по Ду), камеры —
  квадраты, точки подключения подписаны. `result.png` рисуется по выходу сервиса, по панели на вариант;
  спецпроходы — пунктиром.

Как резалось окно. Здания берутся целиком, если задевают окно. Все остальные слои — дороги, линии, парки,
территории, ж/д и вода — обрезаны одинаково, по окну плюс 40 м, поэтому за окном нет пустой полосы, где барьер
есть, а застройки нет. В сценах, где река или полотно перекрывают окно и сцена ждёт неподключения, препятствие
продлено от края данных прямыми полосами на 7 км: обход тогда длиннее 14 км и больше предельной длины Ду 1400
(11 276 м), поэтому неподключение следует из правил. Эталон пути ищется на всём охвате данных. Труба, распавшаяся при обрезке на части,
записана частями с суффиксами `-1`, `-2`. Камера остаётся, только если лежит на оставшейся трубе (до 0,5 м).
Газопровод или кабель, который проходит под новым домом (ввод в снесённые гаражи, линия под пятном застройки),
убран: при строительстве его перекладывают, а в окне он делал бы выход из дома невозможным.

Расходы новых домов взяты из распределения датасета организаторов (17 значений от 4,08 до 76,27 т/ч), выбор по
хэшу id дома. В сценах FLOW и LEN расход задан явно.

## Ожидания

`expect.must` — то, что следует из правил: нарушение означает ошибку сервиса. `expect.should` — то, что сделал
бы опытный проектировщик; отклонение — повод посмотреть картинку, а не обязательно ошибка. `expect.engineer` —
то же словами. Ожидания выведены из правил и геометрии входа, а не из выхода сервиса. Сравнивается вариант с
`rank = 1`.

Кратчайший допустимый путь (`reference`) считается по сетке 2 м: от выхода финального участка за зону отступа
своего здания до любой трубы, в обход зданий с отступом по Ду и запретных территорий с их отступом. Финальный
участок идёт от ближайшей точки внешней границы здания. Газ, кабель, существующая сеть, дороги и трамвай
закрыты вместе с отступом: газ 2 + 0,2 м, кабель 2 + 0,1 м, существующая сеть 1 м плюс её полуширина, дороги и
трамвай 1,5 м (всё плюс полуширина пары). Пересечь их можно только одним прямым участком через всю полосу:
угол к каждой стороне каждого полигона дороги не меньше 45°, к линии — не меньше arcsin(отступ / (отступ + 0,1)),
около 74° для газа: тогда весь участок в зоне отступа лежит в круге «норма + 0,1 м» у пересечения, как требует
check18 (B10, B11). Прямой участок не может пройти в зоне отступа линии, которую не пересекает, в том числе у её
конца. К трубе подход тоже прямой и почти перпендикулярный, и тоже не идёт в зоне отступа чужой линии без её
пересечения: поэтому в трубу, лежащую ближе нормы к газопроводу, со стороны без газа не врезаться. На участке,
где две трубы лежат друг на друге, врезки нет: новая камера дала бы больше четырёх примыканий. В конец трубы
(обычно камеру) можно подойти с любой стороны. Если труба лежит прямо перед точкой подключения, финальный участок
может сразу кончаться на ней. Ж/д, вода и запретные территории непроходимы. Если от ближайшей стены здания пути нет, эталон ищется от любой стены (Р29-15); такие точки
перечислены в `final_from_nearest_boundary_m.except`. Канализация и водопровод (дополнительные типы) в эталоне
проходимы. Ду эталона подбирается по расходу и длине: если найденный путь длиннее предела Ду по расходу, путь
ищется заново с отступами большего Ду. Сетка 2 м удлиняет путь до 8 %. Эталонный путь лежит в `scene.json` (`reference.*.path_wgs84`) и
рисуется на картинке пунктиром: от точки подключения через выход за зону отступа до точки на трубе.

Эталон считается после всех правок окна: если сцена убирает сеть, двигает дом или точку, посчитанный раньше
эталон сбрасывается. Генератор проверяет каждую сцену: эталонный путь начинается в точке подключения и кончается
на трубе, а граница длины не короче расстояния от точки до трубы по прямой. Нарушение печатается при генерации.

Эталон — приближение на сетке, а не готовая трасса. Если собрать выход прямо по `path_wgs84`, check18 часто
находит мелкие нарушения: отступ меньше нормы на сантиметры у линии или здания, поворот больше 90° на стыке
сетки, излом внутри спецпрохода. Поэтому эталон задаёт границу длины, а не форму трассы. Граница
1,5 × эталон + 30 м оставляет запас на обход таких мест. Там, где допустимость эталона вызывает сомнение и
другого пути не видно (AREA-02, BLD-14), подключение стоит в `should` с причиной в тексте инженера.

Жёсткая граница длины проверена на известных допустимых выходах. Из 97 сцен с `must.route_length_max_m` в 94 есть
выход, который проходит `check18 --no-shape --core-types` и укладывается в границу: выход сервиса на том же входе,
ручная трасса облачного ревью или сам эталон, собранный в выход (так проходят 43 эталона из 97). Без такого
доказательства остаются три сцены: SCALE-03 (эталон пересекает дорогу под 43,7° вместо 45°, запас границы 68 м),
BLD-13 (запас 49 м) и LEN-02 (запас 416 м). Скрипты проверки лежат в `.dev/audit5-fix/`.

Если эталонный путь найден, точка стоит в `must.connected`; в `should` подключение уходит только вручную, с
причиной в тексте инженера. Если пути нет, сцена ждёт неподключения. Граница длины пути:
`must.route_length_max_m` = 1,5 × эталон + 30 м и `should.max_route_length_m` = 1,3 × эталон + 10 м. Жёсткая
граница ставится только в сценах с одной точкой: в дереве путь точки идёт через общие участки и может быть законно
длиннее её собственного кратчайшего пути. Оценки S в синтетических сценах посчитаны по идеальной геометрии,
допуск +0,02.

Всем сценам, где ждут выход сервиса, добавлены общие ключи жёстких правил: `max_turn_deg` 90,
`max_segments_any` 4, `no_cycles`, `no_self_cross`, `flow_is_sum`, `no_turn_in_special`, `dn_valid`,
`summary_consistent`, `no_short_reversal_m` 5, `no_step_m` 10, `variants`, `final_from_nearest_boundary_m` 1,
`no_crash`. S, длину и
стоимость проверка пересчитывает по геометрии и таблицам правил; сводку варианта
сверяет с этим пересчётом `summary_consistent`. Если в выходе нет `output.criteria.json`, ожидание `unconnected`
даёт «не проверить»: без файла причину неподключения прочитать нельзя.

Ключ `no_step_m` ловит ступеньки и выступы (п. 2.1, Р5, Р29-18). На пути от точки к сети он ищет два поворота
в разные стороны не меньше 60° каждый, между которыми звенья короче 10 м. Нарушение засчитывается, если прямая
от точки за 10 м до первого поворота до точки через 10 м после последнего короче пути хотя бы на 0,5 м, даёт
на концах поворот не больше 45° и не подходит ни к одному объекту входа ближе нормы отступа, если исходная
трасса сама не подходила к нему ещё ближе. Если рядом дорога, трамвай или подземная линия, прямой нельзя
подходить к ним ближе нормы ни при каких условиях. Порог проверен на выходах сервиса (fix1, r7, r8 из
`.dev/fix-route-runs`, `.dev/audit4/run`, `data/scenes-v3`, всего 636 выходов), 95 собранных эталонах и 9
своих путях пятого аудита: ни одного срабатывания. Из 913 эталонных путей этого набора ключ срабатывает на
одном: в SCALE-13 у точки cp-ren-w882050156 сам эталон у выхода из дома делает зигзаг −98° и 71°, и прямая
короче на 2,9 м. Это огрех сетки эталона, а не правила; скрипты проверки лежат в `.dev/audit5-fix/`. Ступенька 2 м и выступы 2 × 3 и 2 × 6 м из пятого аудита
пойманы, выступы, добавленные на самый длинный прямой участок каждого из 86 выходов r8, тоже. Ключ не видит:
изломы по 45° (их даёт сетка эталона, ловит только полный check18, B18), ступеньки, где внутри есть камера
ветвления или спецпроход, и ступеньки, где прямая прошла бы ближе нормы к зданию или линии.

Ключ `variants`: вариантов не больше трёх, ранги 1…n без пропусков, варианты попарно содержательно различаются
(Р29-8). Два варианта считаются одинаковыми, если у них те же места присоединения (каждое в пределах 10 м), те
же подключённые точки и не меньше 90 % длины трассы каждого лежит в 5 м от трассы другого. Сдвинутая на
несколько метров копия варианта не проходит.

Принятые трактовки:

- TIE-01, TIE-02, TIE-03, TIE-16A требуют в `must` врезки в существующую камеру. По букве п. 2.4 и разъяснения 11
  место врезки выбирает сервис, и сдвиг врезки на 10,1 м от камеры формально допустим, а новая камера Ду ≤ 200
  на 2 млн дешевле врезки. Команда читает разъяснение 29.09 (п. 9) как запрет строить новую камеру рядом с
  существующей и считает такой сдвиг нарушением. В TIE-16A место выбрано так, что от ближайшей стены дома есть
  допустимый путь к трубе ближе 10 м от камеры и он не длиннее кратчайшего пути больше чем на 15 м; иначе
  требование врезки в камеру было бы невыполнимым.
- Отступ у пересекаемой линии проверяется вне круга 3 м вокруг точки пересечения (CROSS-22, CROSS-23).
- Дорога, заданная линией, — «нулевой полигон плюс 3 м» (IN-18).
- В здании с внутренним двором финальный участок идёт от внешнего контура (BLD-15).
- Ду новой камеры — по наибольшему примыканию, включая разрезанную трубу (CROSS-22, CROSS-28, стоимость в
  проверке).
- Поворот на пути точки через камеру ветвления считается поворотом трассы: больше 90° — нарушение (`max_turn_deg`,
  check18 B20). В приложении угол поворота задан для трассы, про угол между ветками в камере правил нет.
- Угол пересечения дороги и трамвая проверяется во всех точках пересечения границы, то есть и на выходе из
  полигона. Р6 говорит о точке входа; на дорогах с непараллельными краями это строже буквы.
- Продольный спецпроход по полигону проезда допустим, если он входит и выходит через границу полигона под углом не
  меньше 45° (обычно через торец проезда). По букве п. 4 угол проверяется в точке входа, поэтому такой проход
  законен; на нём держатся BLD-03 и BLD-19. В CROSS-24A проезд торцов не имеет, и вход из кармана идёт под острым
  углом, поэтому там пути нет.
- Пороги S в REAL-01 и REAL-02 (`score_regression_max`) — регрессионные: лучшее известное решение команды
  (v0.12.0, S 12,6962) плюс 2 %, а не следствие правил.

Проверка `heatscenes.expect_check` не использует код сервиса. Она читает `scene.json`, `input.geojson`,
`output.geojson` (имя меняется ключом `--out`), причины неподключения из `output.criteria.json` (их пишет
сервис рядом с выходом, поле `unconnected_reasons[].reason`), код выхода из `run.json` (`{"exit_code": N}`) и
лог из `output.log`. По каждому ожиданию печатает «выполнено», «нарушено» или «не проверить» с числами и
пишет `expect.json` в папку сцены.

| Ключ | Значение |
|---|---|
| `connected` | эти точки должны быть подключены |
| `connected_any_of` | подключена хотя бы одна из точек |
| `unconnected` | точка без сети, допустимые коды причины сервиса: `no_route`, `enclosed`, `inside_forbidden_zone`, `flow_exceeds_capacity`, `coincident_point` |
| `tie_in` | как присоединиться: `existing_chamber` (с допустимыми `chambers`) или `new_chamber` (на трубах `pipes`) |
| `not_tie_in` | в эти камеры заканчиваться нельзя |
| `no_new_chamber_within_m` | новой камеры ближе `radius_m` к этим свободным камерам быть не должно (правило 10 м) |
| `tie_outside_zone` | место врезки вне полигона ограничения плюс `margin_m` |
| `tie_clear_of_buildings_m` | место врезки не ближе к зданиям |
| `max_segments_at` | предел примыканий к камере после подключения |
| `new_chambers_on_pipe_max` | сколько новых камер можно поставить на трубе |
| `existing_chamber_tie_in_count`, `existing_chamber_tie_in_count_max` | число врезок в существующие камеры |
| `route_length_max_m` | жёсткая граница длины пути от точки до места присоединения: 1,5 × эталон + 30 м |
| `max_route_length_m` | ориентир длины пути: 1,3 × эталон + 10 м |
| `summary_consistent` | сводка варианта сходится с геометрией и таблицами: стоимость обычных и специальных участков (с Kспец), камер, врезок, штраф, итог, длина, S |
| `dn_valid` | Ду участков и камер — целые числа из таблицы 1 |
| `no_short_reversal_m` | нет двух поворотов в одну сторону с суммой больше 90° через звено короче этого |
| `no_step_m` | нет ступенек и выступов: двух поворотов в разные стороны от 60° через звенья короче этого, если прямая замена допустима и короче |
| `variants` | вариантов не больше трёх, ранги 1…n без пропусков, варианты попарно различаются местом присоединения или трассой |
| `total_length_max_m` | длина новой сети по геометрии не больше 1,1 × сумма эталонных путей + 20 м |
| `score_max` | S лучшего варианта, пересчитанный по геометрии и таблицам, не больше |
| `score_regression_max` | то же, но порог регрессионный (по лучшему известному решению) |
| `max_segments_any` | у любой камеры не больше примыканий, ветвление только в камерах |
| `no_cycles` | новая сеть без замкнутых контуров и без второго места присоединения у связной сети (кольцо через существующую), в том числе через технический узел на трубе |
| `no_self_cross` | новые участки не пересекаются вне общих узлов |
