# Задачи: ресёрч алгоритмов трассировки и правил разумной трассы

Критерии — в [requirements.md](requirements.md), гейты — в [GATES.md](GATES.md), находки — в [research.md](research.md).

## Контракт исполнения

- **Режим:** параллельно, unlazy scope `routing-research`. Волна 0 и волны 3–4 выполняет драйвер, волны 1–2 — субагенты, не больше пяти одновременно.
- **Тулчейн и команды:** worktree `../LCT-research` на ветке `research/routing` от `feature/backend-core` (C-2) создан пользователем до запуска, пакет спеки в нём уже лежит; все команды из корня worktree, после `source scripts/gates/env.sh` для jar. Прототипы: `uv run --project tools/research …`. Jar собирается `ensure_jar` из `env.sh`. Все гейты пакета запускаются `node ~/.claude/skills/unlazy/scripts/gate-check.mjs --cwd . --timeout 1800 docs/specs/routing-research/GATES.md`.
- **Гейты:** `CHECK:` в GATES.md одобрил пользователь до запуска через `gate-check --approve`; исполнитель не одобряет проверки сам. Новый или изменённый гейт добавляется с `ABANDON: <id> нужно одобрение пользователя на новую проверку`, работа продолжается.
- **Субагенты:** каждый в своём git worktree от `research/routing`, первым действием `git merge --ff-only research/routing`, коммитят только свои файлы без трейлеров атрибуции и не пушат; драйвер вливает ветку и перепроверяет леджер листа.
- **Интерфейсы** (заполнены до параллельного запуска, менять только через журнал):
  - `heatopt.scene.Scene`: разобранный вход (метры, EPSG:32637), `load(path)`, `generate(cls: "S"|"M"|"L", seed) -> path` через `heatsynth.Preset` и `heatsynth.generate`; `scene_hash()`.
  - `heatopt.graph.VisGraph`: узлы с координатами и типом (`terminal`, `tie_chamber`, `tie_pipe`, `reflex`, `road`), рёбра с длиной, долей спецзоны и `k_special`; `build(scene, rules, dn_guess) -> VisGraph`; `to_json(path)`; правила построения — C-4.
  - `heatopt.model`: `cost(tree: Solution, scene, rules) -> CostBreakdown` по разделам 6–10 CONSTRAINTS.md и `interpretation.md` (расходы по дереву, минимальный диаметр, реконструкция по цепочке `upstream_object_id`, камеры по наибольшему диаметру, врезки, штраф); `score(cost) -> S`; `penalties(tree, rules_quality) -> float` по правилам RQ с ценой; единственная модель стоимости для всех.
  - `heatopt.candidates.<name>.solve(scene, graph, rules, quality, budget, seed) -> Solution` для `ls`, `dp`, `bend`, `master`; `quality` — `None` (режим `off`) или правила с ценой (режим `on`); `budget` — детерминированный бюджет итераций, подобранный так, чтобы расчёт на классе L заканчивался не позже 100 с (NFR-2); при одинаковых `seed` и `budget` результат воспроизводится байт в байт; `Solution(edges: list[polyline], tie_ins: list[TieIn], flows: dict, dn: dict, elapsed: float, meta: dict)`; `heatopt.service.solve(scene, jar) -> Solution` — запуск `java -jar <jar> --cli <вход> <выход>` и разбор варианта `rank = 1` в ту же структуру.
  - `heatopt.exact.solve(scene, graph, rules, time_limit_s) -> Bound(objective, bound, status, elapsed)` и `heatopt.exact.lp_bound(...)`; модель по C-6.
  - `heatopt.metrics`: `compute(input_geojson, output_geojson, rules_quality) -> dict[variant_id, dict[RQ, value]]`, CLI и `--self-test` по AC-2.2; правила читаются из `docs/routing-quality.md` (таблица с колонками `ID | Правило | Уровень | Источник | Формула | Порог | Применение | Цена, руб. | Метод цены`; «порог» для правил `report` — значение, при превышении которого метрика помечается в отчёте). Шесть пар для `--self-test` — `data/synth/{small,medium}-{1,2,3}.geojson` и `data/out/…`, их создаёт `bash scripts/gates/produce.sh` из backend-core (в свежем worktree `data/` пуст); фикстура — `tests/validator/fixtures/{input,output}.geojson`.
  - `heatopt.bench`: `run --classes S,M,L --seeds 1-30 --workers 3` пишет `data/research/scenes.json` и `data/research/results.json` (на сцену: хеш входа, результаты `service`, четырёх кандидатов, `exact`, `lp`, время); `--check` по AC-1.1, AC-1.2, AC-1.4, AC-3.2, NFR-1, NFR-2.
  - `heatopt.report`: строит `docs/research/routing-benchmark.md` и проверяет `docs/research/routing-report.md`; `--check` по AC-1.3, AC-2.3, AC-4.1.
  - Скрипты: `scripts/gates/research_untouched.sh` (сравнивает `src`, `rules/rules.json`, `tools/synth`, `tools/validator`, `tools/pyproject.toml` с `git merge-base HEAD feature/backend-core`, печатает `SERVICE UNTOUCHED`); правила скриптов — C-7.
  - Разрыв на сцене: `(S_alg − S_ref) / S_ref`, где `S_ref` — доказанный оптимум, иначе лучшая граница с пометкой; в AC-1.2 участвуют только сцены с доказанным оптимумом.
