## 1. Границы задачи

- Режим глубины — дополнительная задача (ТП §5, ДР №7). Включается флагом CLI `--depth`; без флага выход 2D и он
  **побайтово не меняется** (эталон на `main` 0.11.0: `data/real/dataset.geojson` → sha256 `bb98d72d702e…`, датасет с
  газом → `b96a15d81413…`; при новых правках 2D в `main` эталон берётся с jar чистого `main`). Город (Москва) — сверять
  геометрию, а не sha: нумерация id камер в городском режиме `main` меняется от прогона к прогону.
- Меняется только профиль поверх готовой 2D-трассы (ТП §5 разрешает не перестраивать маршрут): глубины участков,
  деление участков техническими узлами, Kгл в стоимости, свой ранг вариантов. План, Ду, камеры — из 2D.
- **2D не трогать.** Найденные 2D-ошибки (раздел 11) — отдельные задачи.
- Целевая функция: стоимость (S), затем меньше вертикальных изломов, затем ближе к 3,0 м.

## 3. Конвейер `DepthProfiler.profile()` (стр. 170)

1. `written(variant)` (стр. 1202) — геометрия варианта на сетке выхода: вершины округляются, как их пишет 2D (9 знаков
   градуса), и переводятся обратно в метры. Всё дальше считается на этой геометрии, иначе длина 2-сантиметрового куска
   по записанным координатам расходится с `length` и уклон по геометрии > 0,10.
2. Цепочки (`Chain`, стр. 500): участки от узла (камера, точка ОКС, камера врезки) до узла через технические узлы 2D.
   В конструкторе цепочки:
   - пол (`floors`): спецучасток у дороги или трамвая — верх не мельче 1,0 / 1,2 м по всему профилю (`floor`, стр. 801);
   - точки пересечения газа, кабеля, существующей сети на **любом** участке (`crossings`, стр. 753; `crossPoints`,
     стр. 820): касание у конца участка отбрасывается только для существующей сети у камеры или ОКС (врезка);
   - зоны постоянной глубины (`Pin`): ±2 м по трассе от точки пересечения, расширенные на налегание габаритов в плане
     (труба вдоль сети у врезки); перекрытые зоны — одна; край ближе `SNAP_M` к границе участка дотягивается до неё;
     допустимые глубины зоны — `range(from, to, group)` (стр. 637): «над» h ≤ верх − просвет − H_нов, «под» h ≥ верх +
     H_объекта + просвет, не мельче пола и 0,7;
   - зона за концом цепочки запоминается в `spills`.
3. `spill` (стр. 517): остаток зоны переносится во все цепочки того же узла (зона 2 м идёт через камеру во все ветви),
   не короче 1 см.
4. `chain.solve(nodeDepth)` → `solve(...)` (стр. 838): динамика по зонам цепочки. Кандидаты глубины зоны — `values`
   (стр. 902): границы частей диапазона, ближайшая к 3,0, значения соседних зон, «соседняя глубина ± уклон·расстояние».
   Переход между зонами — `gap(..., floors)` (стр. 952): прямая, если обе глубины не глубже 3,0 (§5: изменённую глубину
   между близкими препятствиями можно сохранять), иначе возврат к 3,0 при первой возможности или встреча уклонов;
   `fits` (стр. 979) проверяет пол дороги по всему переходу. Стоимость перехода — `cost` (стр. 1060, Kгл по концам куска)
   + `BEND_RUB·bends(piece)` (стр. 1044).
5. `free` (стр. 477): если у цепочки нет выполнимого профиля, её узел сдвигается на ближайшую к 3,0 глубину, при
   которой все цепочки узла выполнимы. Порядок: точки ОКС → камеры ветвления → камера врезки.
6. `cheaperNodes` (стр. 307) + `move` (стр. 362): покоординатный спуск по узлам и парам концов короткой глубокой
   цепочки, пока сумма (стоимость + изломы + `chamberPenalty`) падает. Подвижны: точки ОКС (по стоимости), камеры,
   сдвинутые в `free` (на самую дешёвую глубину, ближе к 3,0), остальные камеры — только в ±1 см от 3,0.
7. `exactZones` (стр. 689): у зон глубже 3,0 края возвращаются к точным ±2 м, если так дешевле (кусок у края не короче
   1 см).
8. Цепочки без профиля — `closest` + `manual_review` и запись в `conflicts` (лог «ручная проработка»). По доказательству
   (раздел 6) при свободных узлах такого не бывает.
9. Профиль цепочки (точки `{s, h}`, края зон с флагом «жёсткая точка») режется на участки — `split` (стр. 1100): излом
   ближе `SNAP_M` к концу участка переносится в конец, кроме краёв зон; кусок, проходящий 3,0 м, делится всегда;
   длина и глубины — до мкм; стоимость куска = длина · c(Ду) · Kспец · (Kгл(начало) + Kгл(конец)) / 2. У куска с точкой
   пересечения — `depth_crossings` (стр. 1182).
10. Сводка пересчитывается; камеры получают `depth` (глубина труб в камере).

## 4. Правило камер и флаги

Эксперты 16.10: «трубы, естественно, должны войти в камеру на заданной глубине». Поэтому:

- камера (новая, врезки, существующая) — на 3,0 м ± 1 см; внутри допуска — по стоимости;
- сдвиг — только если иначе профиль с уклоном 0,10 не помещается (`free`), затем на самую дешёвую допустимую глубину,
  ближе к 3,0; в выходе `depth_shifted: true`;
- точка подключения ОКС — не камера, глубина по стоимости (id точек приходят из `VariantEnumerator.connectionByOks`).

Системные свойства (`java -D... -jar ... --cli --depth`):

| Свойство | По умолчанию | Что делает |
|---|---|---|
| `heatnet.depth.chambers` | `fixed` | `free` — камеры по стоимости (версия до встречи; Москва S 369,9164 вместо 369,9488) |
| `heatnet.depth.tieFree` | `true` | при `chambers=free`: `false` — камера врезки только на 3,0 (кроме `free`) |
| `heatnet.depth.cheaperNodes` | `true` | `false` — без выбора узлов по стоимости |
| `heatnet.depth.pairs` | `true` | `false` — без парных ходов |
| `heatnet.depth.straight` | `true` | `false` — между мелкими зонами возврат к 3,0 вместо прямой |
| `heatnet.depth.slack` | `0.998` | запас уклона; меньше 0,998 — строгая проверка может упасть на коротких кусках |

## 6. Почему профиль оптимален (кратко)

Стоимость зависит от глубины только через Kгл ≥ 1, длина горизонтальная, камеры и штраф от глубины не зависят. Значит,
C ≥ C_2D той же трассы + то, что правила делают неизбежным: зона, у которой нет допустимой глубины ≤ 3,0 (вынужденная),
тянет за собой окрестность уклоном 0,10. `tools/validator/depth_bound.py` считает эту границу независимо от сервиса
(числа — из таблиц ТП). Разрыв ≈ 0 ⇒ ниже не опустится никакой профиль по правилам. Профиль по правилам существует
всегда: вся сеть на глубине наибольшего «под» (≤ 5,1 м) допустима. Подробно — `docs/depth-optimization.md`.

## 7. Проверки

| Проверка | Команда | Что значит результат |
|---|---|---|
| Валидатор | `uv run --project tools python tools/validator/check18.py --depth <вход> <выход>` | G1–G8 и E1 должны быть 0; замечания формы плана (B*) — сравнивать с 2D того же входа, они 2D-шные |
| Строгая | `uv run --project tools python tools/validator/depth_strict.py <выход>` | `STRICT OK`; любое нарушение — дефект |
| Сертификат | `uv run --project tools python tools/validator/depth_bound.py [--impl] [--free-chambers] <вход> <выход>` | `DEPTH OPTIMAL` — разрыв в пределах округления; `DEPTH GAP x` — сервис дороже границы; `BOUND FAIL` — граница выше стоимости: граница не нижняя или выход нарушает правила (провал) |

Режимы сертификата: по умолчанию — правила ТП + камеры на 3,0 там, где выход их оставил; `--impl` — то же при уклоне
0,0998 (разрыв с ним показывает точность алгоритма в его модели); `--free-chambers` — без правила камер (разрыв = его
цена). Допуск: 0,005 ₽ на участок + 1 мкм длины и 0,2 мкм глубины в рублях.

Ограничения сертификата (только ослабляют границу): невынужденные зоны не распространяются; от закреплённых камер
учитывается только нижний конус; на выходе с `chambers=free` запускать с `--free-chambers`.

## 10. Решения и откуда они

Документы организаторов ссылок на СП не содержат; эксперт на встрече 16.10 упомянул СП «Тепловые сети», но текст
СП 124.13330.2012 в открытом доступе не найден — пункты СП не использованы. Источники по порядку: ТП и разъяснения →
слова экспертов → практическая логика. Полный список с обоснованиями — `docs/depth-optimization.md`, раздел «Решения,
которых нет в правилах организаторов». Ключевые:

1. Камеры на 3,0 ± 1 см, сдвиг только при невыполнимости (эксперты).
2. При равной стоимости — меньше изломов (эксперты); если меньше изломов стоит денег — дешевле (S первый).
3. Зона ±2 м через камеру во все ветви; на всё налегание габаритов в плане.
4. Пол дороги и трамвая на всём спецпроходе.
5. Спецпроход делится техническим узлом в изломе профиля и на 3,0 м (ТП §2.1, §5).
6. Запас уклона, мкм, профиль на сетке выхода.

## 11. Открытое и известные ограничения

- **2D-ошибки (не исправлялись, предложены отдельные задачи):** точка ОКС ровно на границе полигона при Ду ≥ 500 —
  `no_route`; Ду ≥ 1200 через дорогу или трамвай — `no_route`; суммарный расход > 22 501,9 т/ч — исключение
  (`Rules.diameterFor`); у камеры врезки труба вдоль существующей сети без спецпрохода (Москва, 3 участка; в глубине
  просвет выдерживается); газопровод полигоном — ОКС не подключается.
- Налегание габаритов учитывается в пределах своего участка (`ponytail` в `crossings`); через узел зону продолжает
  `spill` на 2 м.
- Изломы не взвешиваются по углу; «пила» (частичный подъём между двумя близкими вынужденными зонами) остаётся, если она
  дешевле.
- Камеры, сдвинутые `free`, помечены `depth_shifted`; в Москве их 53. Альтернатива по правилам — ручная проработка
  (ДИТ 4.6) или перенос точки врезки (это уже 2D).
- `manual_review` при свободных узлах не возникает; ветка кода — для `chambers`/`tieFree` в жёстких режимах.
- B21 в check18 чувствителен к сдвигу координат в микроны; поэтому профиль строится на сетке 2D-выхода — не менять
  `WGS_SCALE` без `GeoJsonStreamWriter.COORDINATE_SCALE`.

## 12. Как вносить изменения

1. Сначала назвать место дефекта (файл:строка), потом минимальная правка.
2. После правки: тесты; 2D sha неизменен; набор и миры — `граница_выше=0`, `G=0`, `STRICT OK`; реальные наборы —
   сертификат без BOUND FAIL; при правках зон, камер или записи — полный check18 Москвы и сравнение B* с 2D.
3. Каждое новое решение вне правил — в `docs/depth-optimization.md` (раздел решений) с источником: ТП → эксперты →
   логика.
4. Git: работать в отдельной ветке от свежего `origin/main`, в `main` — только по просьбе пользователя; сообщение коммита — одна строка, без трейлеров
   Co-Authored-By/Claude-Session (хук `.claude/hooks/block-claude-coauthor.sh`). После переписывания истории 17.10 не
   пушить старые ветки и `backup/*`.

## 13. Ловушки окружения

- Только Java 11: `source scripts/env.sh`; Gradle только `--no-daemon`.
- Скрипты с pyproj — через `uv run --project tools python ...` (системный python без pyproj).
- Не править bash-скрипт, пока он исполняется (bash читает файл по ходу).
- Шаблон разрыва в скриптах — `разрыв=-\?[0-9.]*` (без минуса отрицательный разрыв терялся).
- Тяжёлые прогоны — в фоне; параллельные JVM искажают время.
- Слово `commit` и строка соавторства в одной shell-команде блокируются хуком — не писать тестовые сообщения с трейлером
  в командах.
