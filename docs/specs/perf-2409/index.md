# Время и качество без регресса

Статус: ✅ готов, гейты G1–G7 в [GATES.md](GATES.md) закрыты 25.09.2026, выход — версия 0.7.0. Замеры и решения — в [отчёте](../../testing/perf-2409-run.md), журнал гипотез — в [hypotheses-1809.md](../../research/hypotheses-1809.md#время-и-качество-2425092026).

## Задача

Найти, где сервис тратит время и теряет качество, и ускорить расчёт так, чтобы вариант 1 не стал хуже ни на датасете организаторов, ни на городе. Правила кейса (`rules/rules.json`, CONSTRAINTS.md, `check18.py`) не менялись.

Точка отсчёта — v0.6.3: датасет организаторов S 13,729 за 7,5 с, «густо» 50/100/200 — 56,126 / 115,644 / 233,268, город — 1056 с, из них 855 с районы до срока 900 с, неподключённых 3 130 660.

## Как шла работа

Профиль JFR показал четыре места: запросы к `STRtree` по огромным рамкам длинных рёбер графа (89 % времени дальних районов города), `STRtree.size()` в циклах по 3 млн точек (он обходит всё дерево), токенизацию Jackson на главном потоке чтения и зоны отступа с углами `JOIN_MITRE`, которые шире правила. По каждому месту работал отдельный агент в своём worktree, каждое заявление перепроверял независимый агент. Три круга:

1. Ускорения без изменения выхода: чтение, пост-фазы города, ядро геометрии. Качество: точные зоны отступа и срезка углов, подключение точек у трубы.
2. Перенос веток качества на сведённую ветку, исправление найденных проверкой дефектов (чтение строками при данных после `features`, ёмкость врезки у срезанного дерева, число вариантов).
3. Параметры поиска, выход из здания по Ду участка, ускорение сборщика.
