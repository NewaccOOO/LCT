# Москва: Хорошёво-Мнёвники и соседи, источник ТЭЦ-16

Вход сервиса по реальной карте. Файлы:

- `input.geojson` — формат раздела 12 CONSTRAINTS.md (`oks_existing`, `oks_future` + `oks_connection_point` с `oks_id`);
- `input_1809.geojson` — формат датасета организаторов (редакция 18.09): все здания и новые ОКС — `restriction/oks`,
  `flow_tph` у точки подключения, опоры ЛЭП — полигоны фундаментов;
- `check.md` — проверки полноты и правдоподобия (`city_geojson.py check`), `build.json` — параметры сборки;
- `map.png` — картинка района (сеть: красный — реальная, оранжевый — восстановленная по схеме, синий — достроенная;
  толщина по Ду; оранжевые полигоны — новые ОКС), `map.html` — офлайн-карта (`scripts/visualize.py`, не в git).

Сборка: `uv run --project tools python scripts/city_geojson.py build moscow --format dataset`, проверка —
`... check moscow`, картинка — `... png moscow [--out out.geojson]`. Слои OSM берутся из выгрузки `.osm.pbf` в
`data/cities/cache/` (первый раз — `uv run --project tools --with osmium python scripts/city_geojson.py fetch moscow`).
Две сборки подряд дают побайтно тот же файл: sha256 `input.geojson` `edf2f1b181126dcbb7c672c620839b79e19452cb8edb9223ab4f641dab157df8`,
`input_1809.geojson` `117d51eccf2fe0416c93d39e3327e75d62114be0cea285e93bc391a0affd2e7c`. Сборка ≈ 12 мин
(Python, растр сети 3 м на 110 км²).

## Район и почему он расширен

bbox **55.760–55.820 с. ш., 37.430–37.600 в. д.** (≈ 10,6 × 6,7 км, 110 км²) вместо предварительного
55.762–55.800 / 37.455–37.535 (21 км²). Причина: городской режим сервиса проверяется при > 500 новых зданий с
точками подключения, а в исходном bbox реальные стройки и свободные участки OSM дают 143 новых дома
(26 `building=construction`, 44 `landuse=construction` на 66 га, 16 brownfield на 23 га, 27 мест снесённых зданий).
Расширение на восток и север (Хорошёвский, Беговой, Сокол, Аэропорт, Пресня до ТТК) охватывает реновацию и
стройки у ТТК и Ходынки и почти весь лист схемы теплоснабжения ТЭЦ-16 (восстановлена Разведчиком): 510 новых ОКС.
Меньшие окна проверены: 47 км² — около 110 домов, 75 км² — около 190.

Почему OSM. Это единственный открытый векторный источник всей застройки и улично-дорожной сети с лицензией,
разрешающей производные наборы (ODbL: атрибуция и та же лицензия для производной базы). Яндекс.Карты и 2ГИС
запрещают автоматическую выгрузку и создание производных наборов — их использовали только глазами для сверки,
данные оттуда не брались. Overpass сначала был основным путём, но 27.09 overpass-api.de и z.overpass-api.de
рвали TLS нашему IP (лимит частоты, параллельно ходил Разведчик), зеркала отвечали 504; поэтому слои берутся из
региональной выгрузки `.osm.pbf` (тот же OSM, одна дата снимка — это ещё и воспроизводимее). Выборка из pbf по bbox
с запасом 300 м кэшируется в `data/cities/cache/osm-<город>-<хэш bbox>.json`; для неё нужен pyosmium
(`uv run --project tools --with osmium ... fetch <город>`), сборке и проверке он уже не нужен.

Производная база `input.geojson` распространяется на условиях ODbL 1.0 с атрибуцией «© участники OpenStreetMap».

### Калибровка нагрузки по расчётным расходам МОЭК

На 868 участках схемы с подписанным расходом `G` (т/ч) и без транзита и достроенных веток ниже сравнили `G` с суммой
расходов по формуле (СНиП 2.04.07-86*, см. ниже) зданий ниже по сети: медиана G / формула = **0,493**, квартили
0,24–1,12. Формула систематически завышает расход вдвое (все `building=yes` считаются отапливаемыми, общая площадь
0,8 от площади этажей, графики МОЭК фактически 135/68 °C). Поэтому для Москвы расходы и `heat_load` всех зданий,
включая новые ОКС, умножены на k = 0,493 (`k_cal` в `build.json`). Разброс велик: вводы схемы привязаны к зданиям
приблизительно, часть нагрузки квартала идёт через ЦТП.

## Решения по слоям

- **Здания** — все `building=*` OSM, задевающие район, целиком (не обрезаются), мультиполигоны с дворами-дырками
  сохранены; `building=construction` — в новые ОКС, `roof`, `no` — не здания. Этажность из `building:levels`/`height`,
  иначе по правилу ниже (`_levels=inferred`).
- **Проезжая часть** — полигоны `area:highway` (real) и оси `highway` с шириной (inferred; с тегом `width` — real).
  Не ограничения: тротуары, дорожки, `service=parking_aisle|drive-through`, мосты и тоннели (труба идёт под мостом и
  над тоннелем, это не пересечение проезжей части).
- **Метро**: только открытые участки `railway=subway` на поверхности (`metro`). Тоннели глубокого и мелкого
  заложения не ограничение: над тоннелями трубы реально проходят (с согласованием метрополитена), а запрет с отступом
  10 м по оси тоннеля разрезал бы город на части, которых в реальности нет.
- **Запретные территории**: военные, кладбища, электростанции и подстанции, места заключения. Здания на них сеть
  города не обслуживает (своё теплоснабжение) и в проверке «дыр» не участвуют.
- **Коммуникации**: газ, кабели, водопровод, канализация OSM — real; остальное по поперечному профилю (ниже).
  Воздушные ЛЭП — только опоры (`power_line_support`), провода не препятствие для подземной трубы.
- **Служебные поля** с `_` (`_source`, `_osm`, `_kind`, `_levels`, `_flow_tph`, `_dn_scheme`, `_flow_scheme_tph`,
  `_adjusted`, `_ring_cut`, `_through_building`, `_transit_tph`, `_ctp`, `_site`) и `levels`, `building`, `highway`,
  `width_m`, `address` сервис игнорирует: прогон `data/samples/small-1.geojson` с добавленными `_source`, `_osm`,
  `levels` даёт побайтно тот же выход без диагностик. Поэтому разметка уровней лежит прямо в файле.

## Поперечный профиль улицы (достроенные коммуникации)

Теплосеть — на своей стороне улицы (где больше её длины), остальные четыре сети — на противоположной. Оси от кромки
проезжей части: кабель 1,5 м, водопровод 2,3 м, канализация 4,0 м, газопровод низкого давления 5,3 м. Нормы
СП 42.13330.2016: до бортового камня (табл. 12.5) водопровод 2,0 м, прочие 1,5 м; между сетями в свету (табл. 12.6)
кабель–водопровод 0,5 м, водопровод–канализация 1,5 м, канализация–газопровод 1,0 м, кабель–газопровод 1,0 м —
межосевые 0,8/1,7/1,3/3,8 м больше норм на полусумму диаметров. До фундаментов (табл. 12.5): кабель 0,6 м,
водопровод 5 м, канализация 3 м, газопровод 2 м — ближе линия обрезается; обрезается и в воде и в 10 м от реальной
сети того же типа. Не прокладываются вдоль второстепенных проездов (`driveway`, `alley`), мостов, тоннелей, автомагистралей.
У каждой улицы четыре линии с id вида `gas-w<id оси>`, `ws-w…`, `sew-w…`, `cab-w…`.

## Правила достраивания

Каждое правило — функция или константа в `scripts/city_geojson.py`, рядом с ней в комментарии источник чисел.

| Что | Правило | Источник чисел |
|---|---|---|
| Этажность без тега (`levels_inferred`) | медиана зданий того же назначения в квартале (кварталы — полигоны между осями улиц), иначе в радиусе 200 м, иначе по назначению (жилые 9, общественные 3, производственные 2) | реальные теги OSM района |
| Площадь этажей | площадь застройки × этажность; у сложных зданий с `building:part` (башни на стилобате) — сумма по частям с их этажностью | OSM |
| Назначение здания | `building=*`; `yes` — по землепользованию квартала; до 80 м² без назначения — неотапливаемое (киоск, будка, ТП) | OSM |

## Новые здания

510 перспективных ОКС с точками подключения (> 500 — городской режим сервиса): **130 реальных** контуров
`building=construction` (`_source=real`) и **380 домов типичной формы** (inferred) на реальных стройплощадках
`landuse=construction`, brownfield/greenfield и местах снесённых зданий (`_site` — id участка OSM). Типичная форма —
медианы по 457 жилым домам района после 2005 г.: 18 этажей, секция 24 × 61 м. Дома не ставятся ближе 5 м к трубам
схемы (охранная зона тепловой сети). Расход 0,13–230 т/ч, медиана 11,4 т/ч (с k = 0,493).

## Прогон сервиса

- Версия входа 18:50 (до переклассификации `building=service` в неотапливаемые): CLI
  `run_cli.sh java -Xmx8g -jar build/libs/heatnet.jar --cli input.geojson out.geojson` завершился **кодом 1 за 10 с**:
  `ArrayIndexOutOfBoundsException: Index 0 out of bounds for length 0` в `TieInFinder.bands`
  (TieInFinder.java:355, `c[0]` у пустой части пересечения буфера спецпрохода с осью трубы) ← `pipeCandidate` ←
  `DirectTies.shared` (городской режим, 510 ОКС). Вход валиден (0 невалидных геометрий, чтение без диагностик).
  stderr — `cli_crash.log`. **Находка про сервис**: падение на валидном входе.
- Финальный вход прогоняет главный разговор; итоги CLI и check18 допишет туда же.

## Что ослаблено и почему

- **0 % сквозь здания**: 41 участок схемы (844 м, 0,09 % длины) остался транзитом через здание — обход растром 1 м
  не находится (узел в проезде под домом, плотная застройка); в Москве так бывает (транзит по техподпольям — 3 %
  магистралей МОЭК, кн. 1.3). Помечены `_through_building=true`, проверка считает их отдельно.
- **Дыры > 150 м**: не проверяются здания на запретных территориях (226 — ТЭЦ, депо, воинские части, кладбища).
- **Источник один**, хотя восток района в реальности питают другие ТЭЦ и РТС: сервис принимает ровно один `source`.
