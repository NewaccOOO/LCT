# Задачи: ресёрч алгоритмов трассировки и правил разумной трассы

Критерии — в [requirements.md](requirements.md), гейты — в [GATES.md](GATES.md), находки — в [research.md](research.md).

## Контракт исполнения

- **Режим:** параллельно, unlazy scope `routing-research`. Волна 0 и волны 3–4 выполняет драйвер, волны 1–2 — субагенты; число одновременных субагентов не ограничено (промт запуска, журнал D-2).
- **Тулчейн и команды:** worktree `../LCT-research` на ветке `research/routing` от `feature/backend-core` (C-2) создал исполнитель на старте (журнал D-1), пакет спеки — первый коммит ветки; все команды из корня worktree, после `source scripts/gates/env.sh` для jar. Прототипы: `uv run --project tools/research …`. Jar собирается `ensure_jar` из `env.sh`. Все гейты пакета запускаются `node ~/.claude/skills/unlazy/scripts/gate-check.mjs --cwd . --timeout 1800 docs/specs/routing-research/GATES.md`.
- **Гейты:** `CHECK:` в GATES.md одобрил пользователь до запуска через `gate-check --approve`; исполнитель не одобряет проверки сам. Новый или изменённый гейт добавляется с `ABANDON: <id> нужно одобрение пользователя на новую проверку`, работа продолжается.
- **Субагенты:** каждый в своём git worktree от `research/routing`, первым действием `git merge --ff-only research/routing`, коммитят только свои файлы без трейлеров атрибуции и не пушат; драйвер вливает ветку и перепроверяет леджер листа.
- **Интерфейсы** (заполнены до параллельного запуска, менять только через журнал):
  - `heatopt.scene.Scene`: разобранный вход (метры, EPSG:32637), `load(path)`, `generate(cls: "S"|"M"|"L", seed) -> path` через `heatsynth.Preset` и `heatsynth.generate`; `scene_hash()`.
  - `heatopt.graph.VisGraph`: узлы `Node(x, y, kind, ref, ignored, capacity)` с типом `terminal`, `tie_chamber`, `tie_pipe`, `reflex`, `road`; рёбра массивами `u`, `v`, `length`, `special_len`, `k_special`, `cost_len` (длина плюс `(k − 1) ×` специальные части); `VisGraph.build(scene, rules, dn_guess, margin=600, points=None, extra_nodes=(), tangent=False)`; `segment(a, b, ignored)` и `visible(xy, targets, ignored)` проверяют произвольные отрезки по тем же зонам; `to_json(path)`; `default_dn(scene, rules)` — диаметр кандидатов, `smallest_dn(scene, rules)` — диаметр нижней оценки; правила построения — C-4. Через узлы `terminal` и `tie_*` путь не проходит.
  - `heatopt.model`: `TieIn(existing_id, existing_type, point)`, `Solution(edges, tie_ins, flows, dn, elapsed, meta)` — рёбра полилиниями в метрах, общие узлы совпадают до 0,05 м, `dn[i]` задан для всех рёбер или ни для одного (тогда модель ставит минимальный диаметр и вставки на ступень выше у предела длины, как сервис); `cost(tree, scene, rules) -> CostBreakdown` собирает вариант выхода (`CostBreakdown.variant` — `heatcheck.model.Variant`) и считает стоимость функциями валидатора; `score`, `rub_to_score`, `objective(tree, scene, rules_quality)` — S или S со штрафами (C-3); `penalties(tree, scene, rules_quality)` зовёт `heatopt.metrics.evaluate`; `shape_metrics(scene, variant)` — повороты, изломы, камеры, врезки по C-9; `validate(scene, tree) -> dict[правило, нарушений]` — правила heatcheck без `schema`, `score`, `variants`; `to_geojson(trees)` — выход в EPSG:4326; `QualityRule(id, title, level, source, formula, threshold, application, metric, price_rub, price_method)` и `unit_prices(rules_quality) -> dict[metric, руб.]`. Сверка T-0: на шести парах `data/out` стоимость совпадает со сводкой сервиса до 0,01 руб., S — до 0,001.
  - `heatopt.tm` — общая основа кандидатов: `edge_weights(graph, dn)` (вес ребра в единицах S), `dijkstra`, `TreeBuilder(scene, graph).build(tie_node, cps, others, weight_dn, weights_for)` — дерево Такахаши–Мацуямы с обрезкой пути в первой точке касания и спрямлением, `Recon(scene, rules).cost(loads)` — реконструкция в единицах S без сборки варианта, `forest(builder, recon, partition)`, `partitions(scene)`, `baseline(scene, graph) -> (Solution, CostBreakdown, trees)` — лучший лес по стратегиям сервиса. Кандидат начинает с `baseline` или своих деревьев и обязан вернуть решение, которое `model.cost` собирает без нарушений.
  - `heatopt.candidates.<name>.solve(scene, graph, rules, quality, budget, seed) -> Solution` для `ls`, `dp`, `bend`, `master`; `graph` строится `VisGraph.build(scene, tangent=True)`; `quality` — `None` (режим `off`) или список `QualityRule` (режим `on`, целевая функция `model.objective`, внутренние оценки ходов могут брать цены из `model.unit_prices`); `budget` — детерминированный бюджет итераций, подобранный так, чтобы расчёт на классе L заканчивался не позже 100 с (NFR-2); при одинаковых `seed` и `budget` результат воспроизводится байт в байт; `heatopt.service.solve(scene, jar, out_dir) -> Solution` — запуск `java -jar <jar> --cli <вход> <выход>` и разбор варианта `rank = 1`. Модуль кандидата задаёт `DEFAULT_BUDGET`; `python -m heatopt.candidates <name> --check` на сценах S-1, S-2, M-1, L-1 проверяет воспроизводимость, сборку без нарушений модели, отсутствие нарушений валидатора на S и M, S не хуже `tm.baseline` и время не больше 100 с на L и печатает `CANDIDATE CHECK OK name=<name> scenes=4`.
  - `heatopt.exact.solve(scene, graph, rules, time_limit_s) -> Bound(objective, bound, status, elapsed, cost_rub, length_m, solution, log)` и `heatopt.exact.lp_bound(scene, graph, rules, time_limit_s) -> Bound`; `graph` строится `VisGraph.build(scene, dn_guess=smallest_dn(...))`; модель по C-6; `objective` и `bound` в единицах S, `log` — путь к логу HiGHS.
  - `heatopt.metrics`: `evaluate(scene, variant, rules_quality) -> dict[RQ, value]`; `compute(input_geojson, output_geojson, rules_quality) -> dict[variant_id, dict[RQ, value]]`, CLI и `--self-test` по AC-2.2; правила читаются `heatopt.rules_check.load(path) -> list[QualityRule]` из `docs/routing-quality.md` (таблица с колонками `ID | Правило | Уровень | Источник | Формула | Порог | Применение | Метрика | Цена, руб. | Метод цены`; «Метрика» — машинное имя значения, которое считает `evaluate`, у правил о поворотах, изломах и камерах — `turn`, `kink`, `chamber`; «порог» для правил `report` — значение, при превышении которого метрика помечается в отчёте). Шесть пар для `--self-test` — `data/synth/{small,medium}-{1,2,3}.geojson` и `data/out/…`, их создаёт `bash scripts/gates/produce.sh` из backend-core (в свежем worktree `data/` пуст); фикстура — `tools/validator/tests/fixtures/{input,output}.geojson`.
  - `heatopt.bench`: `run --classes S,M,L --seeds 1-30 --workers 3` пишет `data/research/scenes.json` (класс, сид, путь, sha256 входа) и `data/research/results.json`; `--check` по AC-1.1, AC-1.2, AC-1.4, AC-3.2, NFR-1, NFR-2. Схема `results.json`: `{started, elapsed_s, workers, budgets: {кандидат: budget}, scenes: [...]}`; у сцены `id` (`S-1`), `class`, `seed`, `hash`, `graph` и `bound_graph` (`nodes`, `edges`, `build_s`), `service`, `candidates: {имя: {off: запуск, on: запуск}}`, `exact`, `lp`. Запуск алгоритма: `status` (`ok`, `failed`, `timeout`), `S`, `S_quality` (S плюс штрафы правил с ценой), `cost_rub`, `length_m`, `elapsed_s`, `turns`, `kinks`, `chambers`, `tie_ins`, `unconnected`, `violations` (`model.validate` по правилам), `seed`, `budget`, `output` (GeoJSON в `data/research/outputs/<сцена>/`). `exact` и `lp`: `status` (`optimal`, `time_limit`, `failed`), `objective`, `bound`, `elapsed_s`, `log`, `log_sha256`. Упавший или вышедший за лимит алгоритм получает свой `status`, сцена остаётся в выборке.
  - `heatopt.report`: строит `docs/research/routing-benchmark.md` и проверяет `docs/research/routing-report.md`; `--check` по AC-1.3, AC-2.3, AC-4.1.
  - Скрипты: `scripts/gates/research_untouched.sh` (сравнивает `src`, `rules/rules.json`, `tools/synth`, `tools/validator`, `tools/pyproject.toml` с `git merge-base HEAD feature/backend-core`, печатает `SERVICE UNTOUCHED`); правила скриптов — C-7.
  - Разрыв на сцене: `(S_alg − S_ref) / S_ref`, где `S_ref` — доказанный оптимум, иначе лучшая граница с пометкой; в AC-1.2 участвуют только сцены с доказанным оптимумом.
