## Контракт исполнения

- **Режим:** параллельно, unlazy scope `city-dataset`. Главный агент делает T-1 и T-2 сам, потом запускает субагентов: волна 3 — тайлы города и три сцены «густо» одновременно (до 10 субагентов, по одному на тайл или сцену), волна 4 — отчёт и прогоны сервиса параллельно. Каждый субагент пишет только в свою папку `data/synth/tiles/<n>/` или свой файл сцены и возвращает путь и числа; сборку и проверку делает главный агент.
- **Тулчейн и команды:** Python через `uv run --project tools`; генератор `python -m heatsynth --preset city|dense-50|dense-100|dense-200 --seed N --out FILE`; проверка `python -m heatsynth.check FILE`; сервис `source scripts/gates/env.sh && java -Xmx12g -jar target/heatnet.jar --cli IN OUT`; гейты `scripts/gates/city_dataset.py`, `city_run.sh`, `dense_run.sh`, `synth_regress.sh`. Всё из корня, ветка `city-dataset`.
- **Интерфейсы:**
  - Пресет `city`: параметры `--tiles N` (число тайлов по стороне, по умолчанию 8), `--tile K` (сгенерировать один тайл в отдельный файл, для субагентов), `--merge DIR` (собрать тайлы в один файл потоком, перенумеровать `id`). Тайл — квадрат города со своей уличной сеткой, здания не пересекают границу тайла; сеть строится одна на город от одного источника: магистраль по тайлам, ветви внутри тайла.
  - Пресеты `dense-50`, `dense-100`, `dense-200`: один квартал не больше 1,5 × 1,5 км, точки подключения в зданиях у сети с расходом, при котором участок требует реконструкции хотя бы у трети ОКС.
  - Сид: `--seed` задаёт весь файл; тайл K использует сид `seed * 1000 + K`.
  - Отчёт `docs/testing/dataset-report.md`: таблица распределений с колонками «организаторы», «город», «густо-200»; строки «медиана вершин здания» и «медиана площади здания» с числами по колонкам; строка «генерация: <секунд> с, <МБ> МБ»; раздел «Как устроена сцена».
  - Статистику для отчёта считает `python -m heatsynth.stats FILE` (новый модуль, потоковый, выборка не меньше 20 000 зданий).
