# Нижний Новгород целиком: 8 районов, сеть по схеме теплоснабжения

Вход сервиса по реальной карте всего города. Файлы:

- `input.geojson` — формат раздела 12 CONSTRAINTS.md, **вариант (а)**: все источники схемы с координатами — `source`;
- `input_1809.geojson` — то же в формате датасета организаторов (редакция 18.09);
- `check.md` — проверки полноты, `build.json` — параметры и сводка сборки;
- `map.png` — весь город, 8 м на пиксель. Сеть: оранжевая — восстановленная по схеме, синяя — достроенная;
  красные круги — источники, оранжевые прямоугольники — перспективные ОКС.

Сборка:

```
uv run --project tools --with osmium python scripts/city_geojson.py fetch nnovgorod   # один раз, кэш OSM
uv run --project tools python scripts/city_geojson.py build nnovgorod --format dataset  # ≈ 2,5 мин, 2,8 ГБ
uv run --project tools python scripts/city_geojson.py build nnovgorod --one-source      # вариант (б)
uv run --project tools python scripts/city_geojson.py check nnovgorod
uv run --project tools --group dev python scripts/city_geojson.py png nnovgorod
```

Две сборки подряд дают побайтно один и тот же файл. sha256 `input.geojson`
`ca2e80f5159183c00f773a44b36eae514373812c05271e927ad674149ce8dd10`.

Сырьё для сборки готовят отдельные скрипты (этап 1):

- `scripts/heat_embed_nn.py osm | embed | avtozavod` → `raw/nnovgorod/restored_heat.geojson`, `restored_unlaid.csv.gz`,
  `teploseti_stats.json`;
- `scripts/heat_future_nn.py` → `raw/nnovgorod/future_scheme.geojson`.

## Территория

Граница — объединение 8 районов (admin_level 9 внутри relation 335495): Автозаводский, Канавинский, Ленинский,
Московский, Нижегородский, Приокский, Советский, Сормовский. Это не bbox: OSM-слои отбираются по полигону с запасом
≈ 500 м. **Кстово не берём.** OSM с 2025 г. включает Кстовский район в городской округ, но схема теплоснабжения города
его не покрывает: в табл. 2.6 Гл. 4 он идёт отдельно, в 8 районов не входит. Поэтому не берутся и 50 строк табл. 2.1
«Кстовский район». Координаты — UTM 38N (EPSG:32638). Для Москвы и СПб зона прежняя, 37N.

### Укладка графа схемы (`heat_embed_nn.py embed`)

**Опорные узлы.** 12 442 узла привязаны к зданиям OSM по адресу (данные Разведчика). Ещё 2 215 потребителей
добавлены ослабленным сопоставлением адреса: числа в названии улицы, дробные номера домов, а из нескольких
подходящих зданий берётся ближайшее к своей компоненте. 282 опоры противоречат соседям (прямое расстояние больше
1,5 × длины по графу + 50 м) и отброшены. Узлы «ЦТП-N / ЦТПО-N / ЦТПГ-N» — это одно здание, в графе они склеены в
один узел. Благодаря этому квартальные сети за ЦТП связаны с магистралью.

**Граф для расстояний.** Улицы, проезды и дорожки OSM плюс решётка дворов 10 м вокруг зданий-опор. Узел решётки
лежит вне здания, а ребро не задевает здания.

**Постановка узлов.** Узел без адреса ставится в точку графа, где расстояния по графу до уже уложенных соседей
лучше всего согласуются с длинами цепочек: минимум Σ((d − L) / (20 м + 0,25 L))². Нужно не меньше двух уложенных
соседей. Если прямых соседей мало, работают ограничения через цепочки неуложенных узлов: до 1,5 км, ожидаемое
расстояние 0,9 длины, допуск 40 %. Затем идёт проход уточнения. Цепочка прокладывается кратчайшим путём (двор
в 1,25 раза дороже улицы), ступеньки решётки спрямляются. Промежуточные узлы ставятся по накопленной длине.

| Метрика | Значение |
|---|---|
| Уложено участков / длины | 37 496 из 41 508 / 1 092,5 из 1 211,9 км (**90,2 %**) |
| `_len_ratio` (длина геометрии / длина по таблице): медиана, IQR | **1,05**; 0,89–1,47 |
| \|ratio − 1\| < 0,25 | 52,7 % участков; 65,9 % по длине; 63,4 % участков от 10 м (хуже всего вводы короче 10 м: у них ошибка в метрах велика в долях) |
| Длина в 30 м от оси проезжей части | 91,9 % |
| Не уложено | 118 км: 102,6 км — у конца цепочки меньше двух опор, 15,1 км — нет пути по графу, 1,7 км — петли и нулевые. Список — `restored_unlaid.csv.gz` |

Во вход идут только трубы отопления: по одной на пару узлов. Трубы ГВС того же канала (261 км) — не теплосеть
отопления.

### Правила достраивания (`heat_embed_nn.nn_network`, `city_geojson.build_nn`)

- **Частный сектор.** Это 29 477 домов: `building=house/detached/…` и жилые здания до 250 м² не выше 2 этажей.
  Отопление у них индивидуальное, как у территорий «Индивидуальное теплоснабжение» в табл. 2.1. Они получают
  `_kind=individual`: не потребители сети и не «дыры».
- **Вне зон ЕТО.** 1 649 жилых и общественных зданий лежат дальше 1 км от сети схемы, вне Автозаводского и
  Ленинского районов. Это посёлки со своим теплоснабжением: `_kind=outside_zone`, к сети не подключаются.
- **Сеть ООО «Теплосети».** В таблице узлов нет, поэтому сеть достраивается лесом кратчайших путей по улицам и
  дворам от Автозаводской ТЭЦ, котельных «Ленинская» и «Северная» к зданиям Автозаводского и Ленинского районов,
  которые дальше 150 м от сети Теплоэнерго. Здание в 150 м от уже проложенной ветки своей ветки не получает, его
  нагрузка идёт на ближайший участок. Ду — по расходу, с монотонностью (`finish_network`). Сверка длины трассы
  отопления:

  | Район | Достроено | По таблице Ч. 5 |
  |---|---|---|
  | Автозаводский | 309,9 км | 258,5 км |
  | Ленинский | 87,3 км | 37,1 км |

  В Ленинском районе часть кварталов вне уложенной сети Теплоэнерго (компонента 4). Ду по таблице — в
  `raw/nnovgorod/teploseti_stats.json`: средний по длине отопления Автозаводский 311, Ленинский 323. Достроенный
  Ду получается из расчётного расхода зданий, а не из таблицы.
- **«Дыры» в остальных районах.** 719 зданий получили ветки от ближайшего узла восстановленной сети, всего 254 км.
  Ещё 4 674 здания покрыты чужими ветками (в пределах 150 м).
- **Разрывы внутри компоненты схемы.** 280 перемычек по улицам до 600 м соединяют куски одной компоненты, которые
  разорвали неуложенные участки. Разные системы не связываются.
- **Источник → сеть.** 59 источников найдены по адресу в узлах схемы, 28 — как ближайший узел компоненты без
  источника (не дальше 300 м). Точка source ставится в узел выхода сети. 27 источников не стоят на уложенной
  сети.
- **Кольца.** Схема кольцевая, а дерево строится от источников, поэтому 957 колец разомкнуты: участок не доходит
  1,5 м до камеры, `_ring_cut`. Узлы ближе 0,3 м склеены.
- **Трубы сквозь здания.** 649 участков обходят здания по растру 1 м (`detour`). 5,9 км, где обхода нет,
  помечены `_through_building`: это транзит через здания, как в схемах Москвы и СПб.
- **Перспективные ОКС.** 674 объекта по табл. 2.1 и 840 строек и свободных участков OSM. В табл. 2.1 — 675 строк;
  суммы площадей и нагрузок по районам сходятся с итогами PDF. Из них 8 районов, без «Индивидуального
  теплоснабжения», — 616 строк. Адрес геокодирован так: здание по адресу — 121, у дома — 34, в границах улиц — 161,
  по улице — 112, у источника — 24. Не привязаны 159 строк, из них 156 — микрорайон котельных
  «Север / Центр / Юг / Заречье» (Советский район): адреса в схеме нет, не выдумывали.

  Контур берётся из стройки OSM у адреса (`real`, 50 шт.), иначе ставится дом типичной формы: 17/12/9/5 этажей
  по площади, секция 16 м (`inferred`). Нагрузка — из схемы, `_load_source=scheme`, делится между домами объекта
  пропорционально площади; `flow_tph = нагрузка × 12,5` (график 150/70). Всего найдено мест для 701 дома, 27
  отброшены проверкой места.
- **Вариант (б), `--one-source`.** Один `source` — Сормовская ТЭЦ. Площадки остальных 116 источников —
  `prohibited_site` с `_heat_source`: `power=plant` из OSM, иначе здание котельной + 10 м, иначе квадрат 30 м.

## Сервис

**Вариант (б)** (`data/cities/cache/nnovgorod/input_b.geojson`, jar v0.9.0 `build/libs/heatnet.jar` из этого
worktree, через `run_cli.sh`, `-Xmx10g`):

- код **0**, 1 780 с (из них 1 625 с — критерии), пик памяти 5,3 ГБ;
- предупреждение «не связаны с источником по стыкам: участков 28, камер 98». Это ожидаемое следствие варианта (б);
- варианты 1–3: подключено 780 из 1 514 ОКС, 734 не подключены (`no_route`: 506 — дома на больших участках OSM,
  228 — из схемы); новая сеть 73,6 км, S = 2 667,05 (рейтинг 1);
- `main`-jar от 26.09 старее поддержки сети без источника и отвергает такой вход (код 2), его не использовать.

**check18** на срезе 3 × 3 км (`scripts/city_cut.py`, 927 участков, 0 неподключённых): 24 нарушения.
- B20 — поворот в камере круче 90°: 6/4/7 по вариантам;
- B21 — излом у камеры: по 1;
- E7/E8 — округление score и порядок рангов после пересчёта среза.

Это находки про сервис, а не про вход.

**Вариант (а)** требует jar прототипа P6 (несколько source) — прогон за главным разговором.

## Что ослаблено и почему

- Координат нет у 106 источников из 223: ведомственные котельные без адреса в OSM. Их компоненты (≈ 150 км)
  — сеть без источника.
- Ду в Автозаводском районе считается по расчётному расходу зданий, а не по таблице Ч. 5: у участков таблицы нет
  узлов и привязки к месту. Сверка длины и Ду — выше.
- Восстановленная сеть идёт по графу улиц и дворов, а не по реальной трассе (листов A0 схемы в открытом доступе
  нет). Отклонение по длине — `_len_ratio` на каждом участке `raw/nnovgorod/restored_heat.geojson`.
- Много не подключено у сервиса: большие участки OSM застроены домами типичной формы далеко от сети, у реки и за
  железной дорогой. Это находка для сервиса и для правил размещения (`future_buildings`).
