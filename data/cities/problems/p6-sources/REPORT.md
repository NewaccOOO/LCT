# P6. Несколько источников тепла (p6-sources)

Отчёт агента P6; записан главным разговором, у агента не было прав на запись файла.

Рекомендация: вариант (а), принимать любое число `source`. Прототип: ветка `worktree-agent-ad18cee7f2c72a4ef`,
коммит 93ee61f, 8 файлов, +89/−42, diff — `p6-multi-source.diff`.

## Проблема
v0.9.0 на каждом `source` после первого пишет диагностику «во входе больше одного источника source»: CLI выходит
с кодом 2, задача REST получает FAILED. Второй источник также срывает параллельное чтение (`SliceMismatch`), и файл
перечитывается последовательно. СПб v1 с тремя реальными источниками (`multi.geojson`) и `tiny-3src.geojson`
отвергаются.

## Причина
Отказ даёт только чтение: `GeoJsonStreamReader.java:439–446` (диагностика), `:1297–1316` (`merge`), `:612–712`
(обход от одной точки), `InputData.source`. Расчёт, выход, критерии, API и check18 источник не используют:
`upstreamId` нигде не читается.

## Сверка с правилами
- «Один источник» (ТЗ 2.2, CONSTRAINTS разд. 4) — упрощение для реконструкции, которую редакция 18.09 отменила.
- П. 1.1 приложения 18.09 число источников не ограничивает; `upstream_object_id` необязателен.
- Разъяснение 11: врезка возможна в любой допустимой точке сети.
- Разъяснение 17: проверка идёт на выгрузках рабочих систем, а в выгрузке района почти всегда несколько РТС или
  котельных. Отказ целиком — риск.

## Варианты
| | (а) несколько `source` | (б) один `source` | (в) файлы по системам |
|---|---|---|---|
| правка | чтение и модель, ~45 строк и 2 теста | нет | скрипты разбиения и склейки |
| датасет | побайтово тот же выход | не меняется | не меняется |
| проверочные данные с 2+ источниками | принимаются | отказ | не помогает |

## Замеры прототипа
- dataset, dataset-corrected, medium-1..3: `out` и `criteria` побайтово равны v0.9.0, S 12,7483.
- СПб с тремя источниками: v0.9.0 — код 2, прототип — S 70,1055, 52/65, выход побайтово равен варианту с одним
  источником; check18 даёт те же 10 нарушений, что spb-v1 (к P6 не относятся).
- `tiny-3src`: три врезки — в сеть ТЭЦ, в сеть котельной и в ничейную сеть; check18 OK.
- Юнит-тесты: 153, 0 упавших, 2 пропущено.
