# ADR-0002: локальный поиск по разбиениям ОКС и ускорение графа

- **Статус:** принято
- **Дата:** 2026-09-16

## Контекст

На датасете организаторов (17 ОКС, 88 зданий с реальными контурами) сервис из ADR-0001 считал 537 секунд и давал вариант с S 26,4: восемь отдельных врезок, звезда трасс к каждому ОКС. Ресёрч на Python ([research.md](../research.md)) показал, что выигрыш дают слияния деревьев — одна врезка и одна реконструкция цепочки вместо нескольких — и что почти всё время Java уходило на повторную геометрию одних и тех же точек запроса.

## Варианты

- Перенести локальный поиск прототипа с хирургией деревьев (привить, отрезать, переложить путь) — плюсы: на прототипе S 15–16 за 120 секунд; минусы: 9–12 дней, мутабельная модель дерева и все вспомогательные операции.
- Локальный поиск по разбиениям ОКС поверх существующего построителя черновиков — плюсы: 150 строк, ходы выражаются через готовый `draft`, ничего не ломает; минусы: каждый ход стоит полной сборки черновика, тонкие ходы по геометрии недоступны.
- Цикл с точной подзадачей (Дрейфус–Вагнер по подмножествам на графе области) — плюсы: на прототипе S 12,5; минусы: 13–19 дней и выигрыш только после 300 секунд расчёта.

## Решение

Второй вариант плюс ускорение графа, без которого поиск не влезает во время: касательные рёбра у выпуклых вершин зон, кэш весов точек запроса до узлов, Дейкстра по массивам без мутации графа, кэш целей дерева в построителе. Правило поворотов вынесено в `TurnRule` и проверяется уже при присоединении ветви. Кандидаты врезки ранжируются грубой стоимостью с реконструкцией. Поиск ограничен числом сборок (`heatnet.search.budget`); предел по стенному времени убран 16.09.2026 ради детерминированности.

## Последствия

Датасет организаторов: 72 секунды и S 16,8 вместо 537 секунд и 26,4; на `medium` 7–9 секунд. Результат поиска зависит от стенных часов, значит от машины; расчёт без поиска детерминирован. Крупные деревья по-прежнему часто отбрасываются правилом поворотов на пути к дальним ОКС (397 из 949 кандидатов на датасете): это следующий резерв, как и цикл с точной подзадачей.

## Как проверить соблюдение

Стенд `scripts/bench.sh` (S и время на датасете организаторов и сценах `medium`) и проверка датасета организаторов `scripts/check.sh organizers`: все точки подключены, проверщик `check18` без нарушений. Как решение развивалось дальше — бюджет сборок вместо предела по времени, правила 18.09, перенос врезки к стволу — описано в [research.md](../research.md).
