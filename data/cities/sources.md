# Источники данных о тепловых сетях Москвы и Санкт-Петербурга

Разведка 27.09.2026. Один проход по всем направлениям: OSM, схемы теплоснабжения, порталы открытых данных,
кадастр (ЗОУИТ), GitHub/Kaggle/OpenInfraMap. Сырьё — `data/cities/raw/<город>/` (GeoJSON, EPSG:4326),
скачанные PDF и ответы Overpass — `data/cities/cache/scout/` (кэш, в git не идёт).

## Коротко

- **Москва: есть реальная сеть с диаметрами.** Схема теплоснабжения Москвы (актуализация на 2026 г.) открыто
  публикует векторные «расчётные схемы тепловых сетей» МОЭК от каждой ТЭЦ/РТС на подложке улиц: трубы, камеры,
  подписи участков «L / Dвн / G». Листы ТЭЦ-16 векторизованы и привязаны к OSM (RMSE ≈ 3 м) →
  `raw/moscow/restored_heat.geojson`: 234 км трассы, 3716 участков с Ду, 1815 камер, 1132 ввода потребителей.
- **Санкт-Петербург: сеть тоже восстановлена** из векторной «Схемы Фрунзенской и Московской магистралей ТЭЦ-22»
  (Купчино и Московский р-н): привязка по контурам зданий к OSM (1072 здания, RMSE 2,6 м) →
  `raw/spb/restored_heat.geojson`: 363 км трассы (магистрали 68 км, распределительные 295 км), 2486 узлов,
  3639 вводов. Ду на листе подписан только у магистралей у ТЭЦ, у остальных участков `diameter` нет.
  Из текстов схемы взяты числа для правил (Ду выводов, длины, график, прокладка).
- **OSM** в обоих городах почти не содержит подземных магистралей: Москва 26,5 км теплотрасс на весь город
  (в bbox Хорошёво-Мнёвников — 0 км), СПб 53,2 км; зато в Москве 748 ЦТП (`man_made=heat_exchange_station`),
  в Купчино 123 люка `manhole=heat`.
- **Порталы и кадастр**: сетей нет. data.mos.ru — косвенные наборы (графики отключения ГВС, ремонты
  коммуникаций, ввод объектов); ЗОУИТ «охранная зона тепловых сетей» на НСПД видна только в интерактивной карте,
  открытой выгрузки/лицензии нет — не брали.

## OSM по районам

Запросы (Overpass, `area` города: Москва 3600102269, СПб 3600337422), ответы в `data/cities/cache/scout/overpass/`:

```
q1: way(area.a)["man_made"="pipeline"]; nwr(area.a)["utility"~"heat"]; node(area.a)["manhole"~"heat"];
    node(area.a)["pipeline"]["substance"~"hot_water|heat|steam"]; nwr(area.a)["man_made"~"heat|boiler"];
q2: nwr(area.a)["power"="plant"]; …["plant:output:hot_water"|"plant:output:steam"|"plant:output:heat"];
    …["building"~"boiler"]; …["industrial"~"heat|boiler"]; …["substation"~"heat"];
    nwr(area.a)["name"~"ЦТП|ИТП|тепловой пункт|котельная|ТЭЦ|РТС|КТС|…"][!"highway"]…  (СПб: только с building)
adm: rel(area.a)["boundary"="administrative"]["admin_level"="8"] (Москва) / ="5" (СПб); out geom;
```

Теги, реально используемые в РФ (taginfo): трубы — `man_made=pipeline` + `substance=hot_water` (12 тыс. в мире) или
`heat` (8 тыс.), старый `type=heat|hot_water`; люки — `manhole=heat` (2,3 тыс.; `heating` — 2 шт.); ЦТП —
`man_made=heat_exchange_station` (+`pipeline=substation`), реже `power=substation`+`substation=heat-exchanger`,
`utility=heating`; котельные — `power=plant` + `plant:output:hot_water`, `industrial=heating_station`
(`building=boiler_house` почти не используется). Сборка: `uv run --project tools python scripts/heat_osm.py <город> data/cities/cache/scout/overpass`.

## Восстановленные слои

### Москва — `raw/moscow/restored_heat.geojson` (сделано)

`uv run --project tools --with pymupdf python scripts/heat_restore_pdf.py <PDF> <streets.json> <out> 39,40,41 "<ref>"`,
где `streets.json` — Overpass `way["highway"]["name"](55.735,37.37,55.835,37.60); out geom;`.

1. Со страницы берутся: трубы (единственная ломаная чёрного цвета толщиной 0,96 pt), камеры (жёлтые квадраты),
   вводы потребителей (красные ромбы), подписи участков `L n / Dвн n / G n` и их выноски (линии 0,24 pt от угла
   рамки подписи до трубы), подписи улиц (кегль 4,3, прописные).
2. Привязка: подписи улиц (≈ 1500–2600 на лист) сопоставлены с одноимёнными улицами OSM; аффинное преобразование
   лист → UTM 37N: начальное — по центрам подписей и улиц с отбрасыванием выбросов, затем 40 итераций «подпись →
   ближайшая точка своей улицы». RMSE: стр. 39 — 2,9 м, 40 — 2,8 м, 41 — 3,0 м; значок ТЭЦ-16 с трёх листов
   ложится в одну точку (±5 м) рядом с контуром OSM.
3. Сеть: отрезки сливаются в цепочки между узлами, режутся по камерам и посередине между выносками соседних подписей;
   Ду = ближайший из ряда сервиса к Dвн (207→200, 309→300, 414→400, 514→500, 612→600, 898→900); участки без подписи
   получают Ду соседнего подписанного участка (`_diameter_from=neighbor`, минимум из соседей).
4. Проверки: все геометрии валидны; одна компонента связности при допуске 1 м (230 км); длина геометрии / длина
   по подписи — медиана 1,06 (квартили 0,94–1,32).

Поля: `_source=restored`, `_class` (`heat_network`, `heat_chamber`, `consumer`, `source`), `diameter`, `d_inner_mm`,
`_diameter_from`, `label_length_m`, `label_flow_tph`, `name` (номер камеры), `_ref`, `_page`, `_georef_rmse_m`.
